      Excel / VBA macros
      
            
      One button instead of an hour fixing a spreadsheet
      
            
      Exports arrive messy: stray spaces, mixed dates, duplicates, numbers stored as text. A macro fixes the same problems the same way every time.
      
            
      ' shortened
Sub CleanWeeklySales()
  Dim ws As Worksheet, r As Long
  Set ws = Sheets("Sales")
  For r = LastRow(ws) To 2 Step -1
    If Trim(ws.Cells(r, 1)) = "" Then
      ws.Rows(r).Delete
    End If
  Next r
  TidyNamesDatesAmounts ws
  ws.UsedRange.RemoveDuplicates Array(1, 2), xlYes
  AddTotalRow ws
End Sub

      The bill arrives
      
            
      A supplier PDF is uploaded, or picked up from the company's shared Microsoft 365 mailbox by a poller that checks it every minute through Microsoft Graph.
      
            
          
      
          
      
            
      Python reads it first
      
            
      pdfplumber pulls the text and the position of every word. My parser uses the invoice's own table header to put code, description, quantity and price in the right columns. Scans go through OCR. Gemini is only the fallback, which keeps it fast, cheap and repeatable.
      
            
          
      
          
      
            
      Every line is checked
      
            
      Each line is compared with the agreed price list. A line is flagged for a credit note only when it is more than 10% over the agreed rate. Monthly statements are recognised and never loaded as bills.
      
            
          
      
          
      
            
      A person approves, then it posts
      
            
      Nothing is approved automatically. One approval posts the cost to the job, creates the bill in Xero with the PDF attached, and files the PDF in SharePoint. Re-running it cannot create duplicates.

      Why I check the numbers, not only the logs
      
      
      £17,814 counted twice.
      
      
      And the system reported success every time.
      
      
      A real example from a client. An automation can run without a single error and still give you wrong numbers. That is why I compare the results with the original records before I call anything done.
      
      
      
        
      What happened
      Company card spending was imported a second time, and the same costs were added to jobs twice. Those jobs looked less profitable than they really were.
      
        
      How I found it
      Not from an error message, because there was none. I compared each job's costs with the original card transactions and found 151 duplicates across 17 jobs.
      
        
      What changed
      I backed up the data, removed the duplicates, and changed the import so that running it twice can never double a cost again.
